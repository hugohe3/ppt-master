# AI 生图：实测表现

[English](../image-generation.md) | [中文](./image-generation.md)

---

PPT Master 通过 [`image_gen.py`](../../skills/ppt-master/scripts/image_gen.py) 生成页面配图；配置、参数和各后端选项见 [`scripts/docs/image.md`](../../skills/ppt-master/scripts/docs/image.md)。本页记录两家推荐服务商在官方 API 上的实际表现，方便你在已知成本和已知失败模式的前提下选择尺寸、质量档和提示词。

- **OpenAI**：`gpt-image-2.5-sunburst`（后端默认）以及 `gpt-image-2.6-sunburst` / `gpt-image-2.6-flare`。实测于 2026-11-05 与 2026-11-08。
- **Gemini**：`gemini-nano-banana-2.1`（后端默认，`thinking_level=MINIMAL`），并以 `gemini-3-pro-image` 作对照。实测于 2026-11-08。

下面每个数字都是当日的单次实测（费用按 `usage` 字段 × 服务商公布单价估算）。服务商会更换模型和价格，引用前请先核对其定价页。

## 计价方式

### OpenAI：按输出 token 计费，token 数跟随短边

图片输出单价 $30 / 1M token（2.5 与 2.6 相同）。token 数取决于尺寸和质量档：

| 16:9 尺寸 | low | medium | high | xhigh |
|---|---|---|---|---|
| 1280x720 | $0.014 | $0.025 | $0.029 | $0.051 |
| 1536x864 | $0.016 | $0.028 | $0.033 | $0.058 |
| 1920x1088 | $0.019 | $0.035 | $0.040 | $0.071 |
| 2560x1440 | $0.026 | $0.048 | $0.056 | $0.099 |
| 3840x2160 | $0.047 | $0.086 | $0.101 | $0.178 |

（gpt-image-2.6-sunburst；2.5 在 `high` 档的 token 数完全相同。）

- 像素数相近时，token 数与**短边的平方**成正比：1:1（1152x1152）是 16:9（1536x864）的 1.8 倍，3:1（2016x672）是 0.6 倍。横竖互换价格不变。
- 720p 以上，token 大致随短边线性增长：3840x2160 的像素是 1536x864 的 6.25 倍，token 只有约 3.1 倍。
- 各质量档相对 `high` 的倍率在各尺寸下基本固定：low ≈ 0.47×，medium ≈ 0.86×，xhigh ≈ 1.78×。
- `max` 实际可用（报错信息里只列出 `low/medium/high/auto`），1536x864 下 $0.13，1024x1024 下 $0.21，约为 `high` 的 4–7 倍。
- 2.6 的 `medium` 用了 2.5 `medium` 的 3.3 倍 token（1536x864 下 924 对 280）；`high` 档两者相同。

### Gemini：按尺寸档固定收费

| 档位 | 16:9 实际像素 | 图片 token | 费用 | 耗时 |
|---|---|---|---|---|
| 1K | 1376x768 | 1120 | $0.036 | 7–10 秒 |
| 2K | 2752x1536 | 1680 | $0.054 | 14–17 秒 |
| 4K | 5504x3072 | 3780 | $0.117 | 23–28 秒 |

- 14 种比例在 1K 下都是 1120 个图片 token。
- 输出一律是 JPEG，没有透明背景选项。
- `thinking_level=HIGH` 多出 900–3100 个思考 token（每张 $0.046–0.063，28–38 秒）。`gemini-3-pro-image` 图片 token 同为 1120，单价是 4 倍（每张 $0.137–0.142）。

## 尺寸与比例限制

| | OpenAI 2.5 / 2.6 | Gemini nano-banana-2.1 |
|---|---|---|
| 比例 | 任意 W:H，最大 3:1；宽高都必须是 16 的倍数 | 14 个固定值：1:1、1:4、1:8、2:3、3:2、3:4、4:1、4:3、4:5、5:4、8:1、9:16、16:9、21:9 |
| 像素范围 | 总像素 655,360 – 8,294,400；长边 ≤ 3840 | 1K / 2K / 4K（该模型不支持 512） |
| 常见坑 | `1920x1080` 会被拒（1080 不是 16 的倍数），改用 `1920x1088` | — |

`image_gen.py` 已经会把任意比例适配到上述规则，只有直接调 API 时才需要关心这些限制。

不同比例下的构图：OpenAI 在 1:3 到 3:1 的 11 种比例下都是按该比例原生构图。Gemini 14 种里 12 种正常；**1:4 和 1:8 会把同一画面竖向重复拼接**（分别约 3 张和 11 张），而不是一张竖长图；4:1 和 8:1 则是正常的单张构图。

分辨率：OpenAI 在 3840x2160 的 `high` / `xhigh` 下，放大到 100% 能看到真实新增的细节；大尺寸下 `low` 明显发糊。Gemini 的 1K / 2K / 4K 都很干净。

## 图片中的文字

两家使用同一批提示词：12 道日常题（英文页面、中文海报标题、76 字中文段落、中英混排 KPI 卡、带数值柱状图、8 步流程图、毛笔字、4×4 表格、照片中的店招、竖排古诗、白板公式、报纸头版）和 10 道极限题（320 字两段正文、生僻字、12 条要点、9:16 海报、8×5 双语表、繁体中文、中英日韩指示牌、32 个数字的财务表、10 节点时间轴、极小号脚注）。

| 题型 | OpenAI（2.6 / 2.5） | Gemini（nano-banana-2.1） |
|---|---|---|
| 标题、标签、要点、KPI 数字、表格、图表数值、多语种指示牌 | 全对 | 全对 |
| 中文段落（76 字与 320 字） | 2.5、2.6、medium/high/xhigh、2560 与 3840 宽全部正确 | 5 张段落图里 4 张各有一处增字或漏字（如"增长中中位数"多了"中"，换行处重复"问"）；4K 版正确 |
| 小字号正文（报纸栏文，约 13 px） | 通顺正确的中文，3840 下同样 | "像中文的乱码"：真字与造出来的字混杂、句子不通——1K、2K、4K、HIGH 思考档和 3-pro-image 都一样 |
| 竖排古诗 | 2.6 在 7 张里有 3 张漏一个逗号；2.5 写错一个字 | 全对 |
| 生僻字（囹圄、龃龉、彧，以及亳州 / 歙县等地名） | 地名正确；低频单字较弱（"彧"全部写错），部分被写成繁体字形 | 地名正确；"囹圄""龃龉"在所有变体（含 3-pro-image）中都写错 |
| 日常题合计（OpenAI 60 张） | 1 处错字、3 处漏逗号 | — |

OpenAI 的 `medium` 和 `high` 在文字正确率上没有差别，差别在版式精致度。

## 编辑已有图片（改字，其余保持不变）

两家都接收一张页面图或照片，加一句指令，例如"把 210 改成 260、把'中'改成'低'，其余不变"。

| | OpenAI `/images/edits` | Gemini（图片 + 指令） |
|---|---|---|
| 改字正确 | 16/16（2.6 Sunburst 与 Flare，各 8 例） | 8/8 |
| 未改动区域 | 扁平页面：平均像素差 1–3（重新编码的噪声）；照片：5–8（整图轻微重绘，构图不变） | 无法直接比较（输出为 1376 宽 JPEG，比较前需缩放）；有一例把标题挪离原位置，一例柱子只略微加高、没到新数值 |
| 费用 / 耗时 | ≈ $0.046（输入 1296 个图片 token + 约 1080 输出），26–35 秒（Flare 约 10 秒） | ≈ $0.038，9–11 秒 |
| Mask | **2.5 与 2.6 均不可用**：上传 mask（alpha 为 0 的区域可编辑）后，该区域在输出里变成纯黑矩形 | 没有 mask 参数 |

两家不带 mask、只用文字指令的编辑都很可靠；OpenAI 的 mask 参数不要用。

## GIF 动图

### OpenAI 2.6：原生 GIF 输出

`image_gen.py --gif-frames N [--gif-frame-ms MS]` 向 `gpt-image-2.6-*` 请求 GIF（直接生成，或用 `--reference-image` 把已有图片做成动图）；参数说明见 [`scripts/docs/image.md`](../../skills/ppt-master/scripts/docs/image.md)。实测事实：

- 2–16 帧；`frame_duration_ms` 生效（测过 100–800 ms）；默认 200 ms，`loop=0`。2.5 模型不支持 GIF。
- 服务端把所有帧拼成一张 sprite sheet 生成后再切开。按帧数的网格：2–8 帧 → 2×4 或 4×2（永远 8 格），9 帧 → 3×3，10–12 帧 → 3×4 / 4×3 / 4×4，13–16 帧 → 4×4。拼图每边 ≤ 3840 px、总像素 ≤ 8,294,400。
- 费用就是那张拼图的 token 费用：1024x576 × 9 帧与 768x432 × 16 帧（拼图都是 3072x1728）在 `medium` 下都约 $0.06。由于 2–8 帧永远按 8 格出图，同样的帧尺寸下帧数少并不更便宜。
- `background=transparent` 可用（加载转圈动画返回了真实的 alpha 通道）。
- 效果好的：旋转、转圈、海浪、粒子、产品转台（完整转一圈且细节一致）、静止的中文标题加移动扫光（9 帧文字完全一致）、标签不动的逐步高亮、柱子长到带数值的最终高度、挥手角色保持一致，以及把已有页面做成动图（箭头长出来，所有文字不动）。
- 失败的：2 帧的离散状态切换（红绿灯只把红灯调暗，绿灯始终没亮）。
- `low` 会让形状逐帧抖动；`high` 比 `medium` 贵 22%，看不出明显改善。Flare 用时约为 Sunburst 的一半，但挥手角色的手出现了半透明重影。

### Gemini：没有 GIF 输出

Gemini 只返回静态图片。让它画 3×3 sprite sheet 再在本地切帧，得不到可用的动图：齿轮的 9 格几乎一样；柱状图的格子大小不均，等分切割后每帧都混进相邻格的内容。

## SVG 输出（OpenAI 2.6，流程未使用）

`output_format=svg` 必须带上未写进文档的字段 `svg: {"model": "<文本模型>"}`，且 `n=1`；只能文本 → SVG（编辑接口不接受 SVG，无法把已有图片转成 SVG）。每张 SVG 约 $0.06–0.09（图片步骤加上由文本模型写 SVG，后者不计入 `usage`）。PPT Master 不调用它；需要矢量图时，自行准备 SVG 并通过图标库接入。
